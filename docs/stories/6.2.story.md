# Story 6.2: Remove Dark Mode

## Status

review

## Story

**As a** developer aligning the site with the Atlas design system,
**I want** dark mode fully removed from the codebase,
**so that** the site renders only the Atlas light theme with no dead theming code, smaller bundle, and no `dark:` utilities to maintain during the re-skin.

## Acceptance Criteria

1. The `ThemeProvider` is removed from `app/layout.tsx` and the file (`components/providers/theme-provider.tsx`) is deleted.
2. The theme-detection inline `<script>` in `app/layout.tsx` (the `scalenty-theme` localStorage block) is removed; `suppressHydrationWarning` removed if no longer needed.
3. The `ThemeToggle` component (`components/ui/theme-toggle.tsx`) is deleted and removed from `header.tsx` and `mobile-nav.tsx`.
4. `darkMode: ["class"]` is removed from `tailwind.config.ts`.
5. All `.dark { ... }` rules and `.dark`-prefixed selectors are removed from `app/globals.css`.
6. All `dark:` utility classes are removed from every component (~14 files identified, incl. `button.tsx`, `result-card.tsx`, `pricing-preview-card.tsx`, `contact-form.tsx`, `pricing-preview.tsx`, plus others).
7. The `LanguageProvider` and all i18n behavior (Epic 5) remain fully intact and working.
8. Theme-related tests are removed (`theme-provider.test.tsx`, `theme-toggle.test.tsx`); any other test referencing the theme toggle / dark mode is updated.
9. `grep -rn "dark:" components app` and `grep -rni "darkmode\|theme-provider\|useTheme\|scalenty-theme\|ThemeToggle" app components` return no live references.
10. `npm run build` succeeds and `npm test` passes.

## Dev Notes

### Why
Atlas is a light-only design (`atlas.css` has no dark theme). Epic 5 introduced dark mode (`scalenty-theme` localStorage, custom `ThemeProvider`). This story reverts the theming half of Epic 5 while **keeping** the i18n half (`scalenty-locale`, `LanguageProvider`, language toggle).

### Known touchpoints (from codebase survey)
- `app/layout.tsx`
  - line 8: `import { ThemeProvider } ...` — remove
  - lines 79–96: theme-detection `<script>` — remove (keep the locale script at 97–113)
  - line 77: `suppressHydrationWarning` — remove (only needed for theme class swap; the locale script sets `lang` which is fine, but verify no hydration warning remains)
  - lines 131 & 140: `<ThemeProvider>` wrapper — unwrap, keep `LanguageProvider` + others
- `components/providers/theme-provider.tsx` — delete file (exports `useTheme`, `scalenty-theme` key)
- `components/ui/theme-toggle.tsx` — delete file
- `components/layout/header.tsx` — remove `<ThemeToggle />` and its import
- `components/layout/mobile-nav.tsx` — remove `<ThemeToggle />` and its import
- `tailwind.config.ts` — remove `darkMode: ["class"]`
- `app/globals.css` — remove `.dark { ... }` (lines ~42–75) and `.dark a...`, `.dark .nav-link` (lines ~104–118)
- `dark:` utilities in ~14 files (button.tsx, pricing-preview.tsx, contact-form.tsx, pricing-preview-card.tsx, result-card.tsx, and others) — strip the `dark:`-prefixed classes, keeping the light/base classes.

### Guardrails
- **Do NOT touch** `components/providers/language-provider.tsx`, `components/ui/language-toggle.tsx`, the `scalenty-locale` script, or any `useLanguage` usage.
- When removing a `dark:` class, remove ONLY the `dark:`-prefixed token(s); never remove the corresponding base class.
- If `ThemeProvider` is imported anywhere else (search!), remove those too.
- Verify `useTheme` is not consumed anywhere before deleting the provider; if it is, remove the consumer usage.
- Ordering vs Story 6.1: 6.1 may have left the `.dark` block in `globals.css`. If so, this story removes it. If 6.1 already removed it, just confirm.

### Testing
- Delete `tests/components/providers/theme-provider.test.tsx` and `tests/components/ui/theme-toggle.test.tsx`.
- Update `tests/components/layout/header.test.tsx` and `mobile-nav.test.tsx` if they assert the theme toggle is present.
- Update `button.test.tsx` if it asserts on a `dark:` class string.
- Run full `npm test`.
