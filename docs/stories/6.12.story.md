### `next/og` (Satori) constraints — read before editing the OG files
- **`export const runtime = "edge"`** is required by these files today — keep it (Satori/`ImageResponse` runs on the edge runtime).
- **Satori is NOT a browser** — it renders a Flexbox/SVG subset. It supports inline `<svg>` with `<path fill="…">`, `display:flex`, gradients, web-safe styles. It does **not** run React components, `<img>` to arbitrary remote URLs without fetch, or full CSS. So: inline the mark's `<path>`s; use explicit `fill`/`color` hex (the Atlas tokens aren't available as CSS vars in Satori — use the literal hex values).
- **Metadata-file convention**: Next detects `app/opengraph-image.tsx` / `app/twitter-image.tsx` by the **filename** and reads `alt`/`size`/`contentType`/`runtime`/`default`. If you extract a shared helper, the **route files must still export** those names (re-export from the helper) — a helper in `app/_og/` (underscore folder = not a route) or `lib/` won't be picked up as a route itself, which is what you want.
- **Verification**: there is **no test** on these routes. `next build` compiling the OG/Twitter routes (they appear in the build output as `○ /opengraph-image` etc.) is the green signal. Then eyeball the rendered PNG if you can (`/opengraph-image` in dev).

### `app/favicon.ico` vs `app/icon.svg`
Next's metadata convention: `app/icon.svg` → `<link rel="icon" type="image/svg+xml">` (modern browsers); `app/favicon.ico` → the legacy `/favicon.ico`. With both present, modern browsers use the SVG. The current `favicon.ico` is a Dec-3 binary from the old blue brand (you can't easily recolor a binary `.ico` by hand). **Recommended: delete it** so only the Atlas `icon.svg` is served; modern targets are fully covered.
